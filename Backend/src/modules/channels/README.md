# Channels and messaging data

## Firestore documents

- `channels/{channelId}` stores a workspace-scoped public/private channel or a
  direct/group conversation. It contains the channel type, visibility, topic,
  creator, archive state, and last-message timestamp.
- `channels/{channelId}/members/{userId}` stores membership and per-user
  collaboration state (`joinedAt`, `lastReadAt`, `lastReadMessageId`,
  `lastSeenAt`, and an expiring `typingExpiresAt` value).
- `channels/{channelId}/messages/{messageId}` stores one message, sender
  snapshot, optional parent message, mentions, edit/delete state, and bounded
  reaction counts. It references uploads by ID. Message bodies are never
  embedded in the channel document.
- `channels/{channelId}/messages/{messageId}/reactions/{reactionId}` stores a
  user's unique reaction to a message.
- `channels/{channelId}/uploads/{uploadId}` stores private attachment metadata
  and the server-only Storage object path. Uploads are available only to
  conversation members through short-lived signed URLs generated by the
  authenticated API.

The backend verifies workspace and channel membership for each operation. A
public channel can be discovered and read by workspace members; posting
requires joining. Private channels and direct/group conversations require an
explicit member record. A direct conversation's ID is a hash of the workspace
and sorted member UIDs, so two users cannot create duplicate one-to-one
conversations by reversing participant order.

## Queries and indexes

- Channel lists query `channels` by `workspaceId` and filter active channel
  records in the repository.
- Conversations query by `workspaceId` and filter direct/group records, then
  verify the caller's member document.
- Message history queries a conversation's `messages` subcollection by
  `parentMessageId` and `createdAt`, with a bounded page size.
- A Firestore composite index may be required for `parentMessageId` plus
  `createdAt` ordering. Create it from the Firestore console's missing-index
  link when the query is first deployed.
- Message search is intentionally bounded to the latest 500 messages in the
  selected conversation. It is not a workspace-wide full-text index.

## Realtime and presence

The authenticated Express API authorizes a Firestore Admin SDK listener before
opening an SSE stream. The stream contains invalidation events only; clients
refetch message pages through the authorized API. Workspace-membership
revocation closes the stream. Presence uses short-lived typing expiry and a
last-seen heartbeat; it does not claim authoritative device disconnect
detection. Message uploads are limited to 10 MB, validated by file signature,
and restricted to image, PDF, and plain-text formats. Orphan cleanup for files
uploaded but never attached is not automated in this phase.
